The following changes to the `mapping.xml` file are part of the Cloud Connector 5.6.0 release (CC 5.6.0).

If you are using a custom `mapping.xml` file, you need to manually apply these updates. See [Manage Customization with Newer Releases](/integration/external-integrations/freshservice-integration/customize-freshservice#manage-customization-with-newer-releases).

## Software Tasks

Software with the `ignored` software type is no longer copied to Freshservice.

The following condition was added to the `doql` attribute of the `<resource>` element in this `Software` task:

```xml
<task enable="true" name="Software" type="software" description="Copy Softwares from Device42 to Freshservice using DOQL">
```

```sql
where lower(software_type) != 'ignored'
```

The following condition was added to the `doql` attribute of the `<resource>` element in these four tasks:

```xml
<task enable="true" name="Software In Use" type="software_installation" description="Create Software Install from Software In Use" d42_min_version="16.19.00">
<task enable="true" name="Software In Use" type="software_installation" description="Create Software Install from Software In Use" d42_max_version="16.18.02">
<task enable="true" type="software_installation" description="Delete software installations from Freshservice that do not exist in Device42" d42_min_version="16.19.00">
<task enable="true" type="software_installation" description="Delete software installations from Freshservice that do not exist in Device42" d42_max_version="16.18.02">
```

```sql
and lower(view_software_v1.software_type) != 'ignored'
```

## Devices Tasks

The `Devices` tasks that copy servers from Device42 to Freshservice received several changes. Version 10.0 also splits the DOQL v2 task for Device42 19.04.00 and later into two tasks. See [Device42 19.08.00 Task Versions](#device42-190800-task-versions).

### Hostname Logic Updated

The `alias` CTE was removed from the `Devices` tasks. The hostname now comes from the device name, and a `CASE` expression removes the domain part.

**DOQL v2 for Device42 19.04.00 and Later**

In this task, the `doql` attribute of the `<resource>` element was changed:

```xml
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_min_version="19.04.00">
```

The `alias` CTE was changed from:

```sql
,alias as ( SELECT device_fk,     string_agg(alias_name, ', ' order by alias_name) as hostname FROM view_devicealias_v1 GROUP BY device_fk)
```

To the following `device_hostname` CTE, which uses the guest hostname and ignores placeholder values:

<details>
  <summary>Click to expand the code block</summary>

```sql
, device_hostname AS (
   SELECT device_pk,
          COALESCE(
          NULLIF(
                  CASE WHEN details->>'guest_hostname' ~* '^(none|null|unknown|n/a)$'
                         OR details->>'guest_hostname' ~* '^(localhost|tmpl)(\..*)?$'
                         THEN NULL
                         ELSE details->>'guest_hostname'
                  END, ''),
                  name
          ) AS raw_hostname
   FROM view_device_v2
   )
```

</details>

The `hostname` field was changed from:

```sql
COALESCE(alias.hostname, view_device_v2.name) AS hostname,
```

To the following:

<details>
  <summary>Click to expand the code block</summary>

```sql
CASE
    WHEN device_hostname.raw_hostname ~* '^[^.]+\..+\.[a-zA-Z][a-zA-Z]+$'
    THEN SPLIT_PART(device_hostname.raw_hostname, '.', 1)

    WHEN device_hostname.raw_hostname ~* '^[^.]+\.(localdomain|localdom|local|lan|internal|intranet|home|corp)$'
    THEN SPLIT_PART(device_hostname.raw_hostname, '.', 1)

    ELSE device_hostname.raw_hostname
END AS hostname,
```

</details>

The join was changed from:

```sql
LEFT OUTER JOIN alias                 ON view_device_v2.device_pk      = alias.device_fk
```

To the following:

```sql
LEFT OUTER JOIN device_hostname       ON view_device_v2.device_pk      = device_hostname.device_pk
```

**DOQL v2 for Device42 16.19.00 to 19.03.99**

In this task, the `alias` CTE and its join were deleted from the `doql` attribute of the `<resource>` element:

```xml
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_max_version="19.03.99" d42_min_version="16.19.00">
```

The following CTE was deleted:

```sql
,alias as ( SELECT device_fk,     string_agg(alias_name, ', ' order by alias_name) as hostname FROM view_devicealias_v1 GROUP BY device_fk)
```

The following join was deleted:

```sql
LEFT OUTER JOIN alias                 ON view_device_v2.device_pk      = alias.device_fk
```

The `hostname` field was changed from:

```sql
COALESCE(alias.hostname, view_device_v2.name) AS hostname,
```

To the following:

<details>
  <summary>Click to expand the code block</summary>

```sql
CASE
    WHEN view_device_v2.name ~* '^[^.]+\..+\.[a-zA-Z][a-zA-Z]+$'
    THEN SPLIT_PART(view_device_v2.name, '.', 1)
    WHEN view_device_v2.name ~* '^[^.]+\.(localdomain|localdom|local|lan|internal|intranet|home|corp)$'
    THEN SPLIT_PART(view_device_v2.name, '.', 1)
    ELSE view_device_v2.name
END AS hostname,
```

</details>

**DOQL v1 for Device42 Up to 16.18.02**

The same changes as the DOQL v2 (16.19.00 to 19.03.99) task were made within this task, with the exception that the DOQL query references `view_device_v1` instead of `view_device_v2`:

```xml
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v1" d42_max_version="16.18.02">
```

The `alias` CTE and the `LEFT OUTER JOIN alias` join were deleted. The `hostname` field was changed from:

```sql
COALESCE(alias.hostname, view_device_v1.name) AS hostname,
```

To the following:

<details>
  <summary>Click to expand the code block</summary>

```sql
CASE
    WHEN view_device_v1.name ~* '^[^.]+\..+\.[a-zA-Z][a-zA-Z]+$'
    THEN SPLIT_PART(view_device_v1.name, '.', 1)
    WHEN view_device_v1.name ~* '^[^.]+\.(localdomain|localdom|local|lan|internal|intranet|home|corp)$'
    THEN SPLIT_PART(view_device_v1.name, '.', 1)
    ELSE view_device_v1.name
END AS hostname,
```

</details>

### Last Login and MAC Address Queries Updated

Two CTEs in the `doql` attribute of the `<resource>` element were refactored in these two tasks:

```xml
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_min_version="19.08.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_max_version="19.07.99" d42_min_version="19.04.00">
```

The `devicelastlogin` CTE now gets the end user email from a separate `enduser_by_sid` CTE instead of a subquery. It was changed from:

<details>
  <summary>Click to expand the code block</summary>

```sql
devicelastlogin AS (
    with sub as ( SELECT dll.device_fk, dll.username, dll.domain, dll.sid, ROW_NUMBER() OVER(PARTITION BY dll.device_fk ORDER BY dll.last_login DESC, dll.devicelastlogin_pk DESC) AS rank FROM view_devicelastlogin_v1 dll )
    SELECT sub.*,
     CASE
       WHEN sub.sid IS NOT NULL AND sub.sid <> ''
       THEN (
         SELECT enduser.email
         FROM view_enduser_v1 enduser
         WHERE enduser.details ->> 'sid' = sub.sid
         ORDER BY enduser.enduser_pk DESC
         LIMIT 1
       )
       ELSE NULL
     END AS enduser_email
     FROM sub
     WHERE rank = 1
)
```

</details>

To the following:

<details>
  <summary>Click to expand the code block</summary>

```sql
devicelastlogin AS (
    with sub as ( SELECT dll.device_fk, dll.username, dll.domain, dll.sid, ROW_NUMBER() OVER(PARTITION BY dll.device_fk ORDER BY dll.last_login DESC, dll.devicelastlogin_pk DESC) AS rank FROM view_devicelastlogin_v1 dll ),
    enduser_by_sid as ( SELECT DISTINCT ON (enduser.details ->> 'sid') enduser.details ->> 'sid' AS sid, enduser.email FROM view_enduser_v1 enduser WHERE enduser.details ->> 'sid' IS NOT NULL AND enduser.details ->> 'sid' <> '' ORDER BY enduser.details ->> 'sid', enduser.enduser_pk DESC )
    SELECT sub.*,
     eus.email AS enduser_email
     FROM sub
     LEFT JOIN enduser_by_sid eus ON eus.sid = sub.sid
     WHERE rank = 1
)
```

</details>

The `network_hw` CTE now uses `DISTINCT ON` instead of a `min()` subquery. It was changed from:

<details>
  <summary>Click to expand the code block</summary>

```sql
,network_hw as (
    select
        n.device_fk,
        n.hwaddress
    from view_netport_v1 n
    where n.netport_pk in (
        select min(n.netport_pk) as netport_pk
        from view_netport_v1 n
        where n.device_fk is not null and n.hwaddress is not null AND LENGTH(TRIM(n.hwaddress)) = 12
        group by n.device_fk
    )
)
```

</details>

To the following:

<details>
  <summary>Click to expand the code block</summary>

```sql
,network_hw as (
    select distinct on (n.device_fk)
        n.device_fk,
        n.hwaddress
    from view_netport_v1 n
    where n.device_fk is not null and n.hwaddress is not null AND LENGTH(TRIM(n.hwaddress)) = 12
    order by n.device_fk, n.netport_pk
)
```

</details>

### Change Detection Field Updated

The `doql-suffix` attribute of the `<mapping>` element now uses `last_changed` instead of `last_edited` in all four `Devices` tasks:

```xml
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_min_version="19.08.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_max_version="19.07.99" d42_min_version="19.04.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_max_version="19.03.99" d42_min_version="16.19.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v1" d42_max_version="16.18.02">
```

In the three DOQL v2 tasks, the `doql-suffix` was changed from:

```sql
where view_device_v2.last_edited>'%s'
```

To the following:

```sql
where view_device_v2.last_changed>'%s'
```

In the DOQL v1 task, `view_device_v1.last_edited` was changed to `view_device_v1.last_changed` in the same way.

### Unmapping Query Updated

The `doql-suffix` attribute of the `<unmapping>` element now also matches the cloud instance name and the part of the device name after a `/`. This change was made in the same four `Devices` tasks.

In the three DOQL v2 tasks, the `doql-suffix` was changed from:

```sql
where view_device_v2.name='%s'
```

To the following:

```sql
where '%s' IN (view_device_v2.name, CASE WHEN position('/' IN view_device_v2.name) > 0 THEN substring(view_device_v2.name FROM position('/' IN view_device_v2.name) + 1) ELSE COALESCE(NULLIF(ci.instance_name, ''), view_device_v2.name) END, ci.instance_name) ORDER BY CASE WHEN view_device_v2.name = '%s' THEN 0 ELSE 1 END
```

In the DOQL v1 task, the `doql-suffix` was changed from:

```sql
where view_device_v1.name='%s'
```

To the following:

```sql
where '%s' IN (view_device_v1.name, CASE WHEN position('/' IN view_device_v1.name) > 0 THEN substring(view_device_v1.name FROM position('/' IN view_device_v1.name) + 1) ELSE COALESCE(NULLIF(ci.instance_name, ''), view_device_v1.name) END, ci.instance_name) ORDER BY CASE WHEN view_device_v1.name = '%s' THEN 0 ELSE 1 END
```

In the `mapping.xml` file, the `>` character in these values is written as `&gt;`.

<details>
  <summary>Click to expand the code block</summary>

```sql

    SELECT rel.*
    FROM view_applicationgrouprelationship_v2 rel
    WHERE rel.effective_to IS NULL

lb_target_rels AS MATERIALIZED (

        resource.resource_name AS resource_name,

        AND rel.relation = 'elb_target_groups'

google_vrf AS MATERIALIZED (

        vrf.details ->> 'self_link' AS vrf_self_link
    FROM view_vrfgroup_v1 vrf
    INNER JOIN view_cloudinfrastructure_v2 infra
        ON vrf.cloudinfrastructure_fk = infra.cloudinfrastructure_pk
    INNER JOIN view_vendor_v1 vendor
        ON infra.cloud_vendor_fk = vendor.vendor_pk
```

## Changes to All Tasks

The following changes apply across many tasks in the `mapping.xml` file.

### Unmapping and d42url Elements Added

Each task that syncs items from Device42 to Freshservice assets now has an `<unmapping>` element and a `<d42url>` element. If a task did not have one of these elements, it was added.

If the `resource` attribute of the `<d42url>` element referenced a field that the `doql` attribute of the `<resource>` element did not select, the `doql` attribute was updated to select that field.

### Keyset Pagination Added

A `doql-page-key` attribute was added to the `<resource>` element of every task. The Cloud Connector uses this attribute to get data in pages with keyset pagination, instead of getting all data at once. This improves performance. Where the `doql-page-key` value needed a new field, the `doql` attribute was also updated to select it.

The `Software In Use` and `Delete software installations from Freshservice that do not exist in Device42` tasks also have new `doql-page-source` and `doql-page-source-key` attributes on the `<resource>` element to support keyset pagination.

To use keyset pagination in an existing custom mapping, you must add the `doql-page-key` attribute to your tasks.
