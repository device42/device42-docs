The following changes to the `mapping.xml` file are part of the Cloud Connector 5.7.0 release (CC 5.7.0).

If you are using a custom `mapping.xml` file, you need to manually apply these updates. See [Manage Customization with Newer Releases](/integration/external-integrations/freshservice-integration/customize-freshservice#manage-customization-with-newer-releases).
## Devices Tasks

All four Devices tasks gained a **Vendor** field and a **Virtual Machines** field. The **Vendor** field maps the existing `purchase_order_vendor` column to the Freshservice `vendor` field, looked up by `name` in `vendors`. The **Virtual Machines** field appears under the `VMware VCenter Host` header and maps a new `vms_json` column to `virtual_machines`. That column comes from a new `host_vms` CTE, which lists the VMware VMs registered on each ESXi host. The incremental mapping suffix now compares `GREATEST(last_changed, host_vms.max_vm_last_changed)` with the last sync time, and it always includes ESXi hosts (`virtual_host` and `os_name` like `%esxi%`).

The two tasks with `d42_min_version="19.04.00"` or later have three more changes. A new `bios_shared` CTE finds BIOS UUIDs that more than one device shares. For a VMware VM, `uuid` is now the lowercased BIOS UUID only when that UUID is unique. Otherwise it is `concat_ws('_', vm_manager_instance_id, vm_manager_ref_id)`, and the VM's `instance_id` now ends in `vm_manager_ref_id` instead of the UUID. A new `bios_uuid` column was added, and the **Bios UUID** field under the `VMware VCenter Host`, `VMware VCenter VM`, and `VMware VCenter Image` headers now maps from `bios_uuid` instead of `uuid`.

**Applies to:**

```xml
<task name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" enable="true" d42_min_version="19.08.00">
<task name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" enable="true" d42_min_version="19.04.00" d42_max_version="19.07.99">
<task name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" enable="true" d42_min_version="16.19.00" d42_max_version="19.03.99">
<task name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v1" enable="true" d42_max_version="16.18.02">
```

## Software Tasks

The existing Software task gained `d42_max_version="19.06.99"`, and a new Software task with `d42_min_version="19.07.00"` was added. The first header below is that task before the max version was added. In both tasks, software is now grouped by `lower(trim(name))`, `last_changed` uses `max` instead of `min`, and the **Application Type** field has `skip-update="true"`. In the `d42_min_version="19.07.00"` task, Application Type now comes from the Device42 deployment type (`'saas'`, `'mobile'`, `'desktop'`, and `'server'` as `'desktop'`) instead of always being `'desktop'`.

**Applies to:**

```xml
<task name="Software" type="software" description="Copy Softwares from Device42 to Freshservice using DOQL" enable="true">
<task name="Software" type="software" description="Copy Softwares from Device42 to Freshservice using DOQL" enable="true" d42_max_version="19.06.99">
<task name="Software" type="software" description="Copy Softwares from Device42 to Freshservice using DOQL" enable="true" d42_min_version="19.07.00">
```

## Create Relationship Between Host and Virtual Machine Task

The `vm_device` CTE now excludes VMware VMs with `lower(coalesce(d.virtual_subtype, '')) <> 'vmware'`.

**Applies to:**


## Delete Asset Relationships Tasks

In all three tasks, the `vm_device` CTE now excludes VMware VMs with `lower(coalesce(d.virtual_subtype, '')) <> 'vmware'`, the same change as the Create relationship between Host and Virtual Machine task.

The tasks with `d42_min_version="19.05.00"` or later also dropped the VMware vCenter `UNION` branches, along with their `rels`, `datacenters`, `datastores`, and `networks` CTEs. Those branches used these relationship pairs:

- `'Contains'` / `'Contained By'`
- `'Used By'` / `'Uses'`
- `'Provides storage for'` / `'Stored on'`
- `'Has Registered'` / `'Is Registered On'`
- `'Provides'` / `'Provided By'`
- `'Connects'` / `'Connected By'`
- `'Defines Resources for'` / `'Gets Resources from'`
- `'Has'` / `'Is Attached To'`

Five database `UNION` branches were added, each keyed by `FORMAT('Resource-%s', ...)`. One relates a database instance to its device (`FORMAT('Device-%s', d.device_pk)`) as `'Hosted On'` / `'Hosts'`. The other four use `'Contains'` / `'Contained By'`: database instance to database or schema, database instance to database file, database or schema to database file, and database instance to database instance (`'db_instance_container'`).

**Applies to:**

```xml
<task type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" enable="true" d42_min_version="19.08.00">
<task type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" enable="true" d42_min_version="19.05.00" d42_max_version="19.07.99">
<task type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" enable="true" d42_max_version="19.04.99">
```

## Delete Assets Task

The resource part of the DOQL query (`format('Resource-%s', r.resource_pk)`) now skips VMware vCenter resources, using a `( ... ) is not true` filter. The filter covers five cases:

- `r.category @> ARRAY['vmware', 'vdisk', 'vcenter']` with `vendor_resource_type = 'Disk'`
- `'vcenter' = ANY(r.category)` with `'Network'`
- `'vcenter' = ANY(r.category)` and `'ds'` with `'Mountpoint'`
- `'vcenter' = ANY(r.category)` with `'Datacenter'`
- `'vcenter' = ANY(r.category)` with `'Resource Pool'`

**Applies to:**

```xml
<task type="asset" description="Delete assets from Freshservice that do not exist in Device42" enable="true">
```

## D42 Azure Network Interface to Freshservice Azure Network Interface Task

The **Item Name** field (`item_name` under the `Network Interface` header) was removed, along with the `netport.port AS item_name` column in the DOQL query.

**Applies to:**

```xml
<task name="D42 Azure Network Interface to Freshservice Azure Network Interface" type="asset" description="Copy Azure Network Interface from Device42 to Freshservice" enable="true" d42_min_version="19.04.00">
```
