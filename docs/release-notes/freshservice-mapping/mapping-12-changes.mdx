The following changes to the `mapping.xml` file are part of the Cloud Connector 5.7.0 release (CC 5.7.0).

If you are using a custom `mapping.xml` file, you need to manually apply these updates. See [Manage Customization with Newer Releases](/integration/external-integrations/freshservice-integration/customize-freshservice#manage-customization-with-newer-releases).

## Devices Tasks

The `Devices` tasks received five changes. The first three apply to all four `Devices` tasks:

```xml
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_min_version="19.08.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_max_version="19.07.99" d42_min_version="19.04.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_max_version="19.03.99" d42_min_version="16.19.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v1" d42_max_version="16.18.02">
```

### Vendor Field Added

The Device42 purchase order vendor now syncs to the Freshservice **Vendor** field.

The following field element was added to the `<mapping>` element:

```xml
<field resource="purchase_order_vendor" source-type="string" target="vendor" target-field="id"
       target-type="dict" target-foreign="vendors" target-foreign-key="name" max-length="255"
       resource-description="Vendor of the qualifying purchase line item with the latest end date (warranty, or base/upgrade from IBM/Lenovo)"
       resource-description-manual="true" target-description="Vendor"/>
```

### Virtual Machines Field Added

VMware ESXi hosts in Freshservice now show the VMs registered on them in a new **Virtual Machines** field.

A new `host_vms` CTE was added to the `doql` attribute of the `<resource>` element. In the three DOQL v2 tasks, the CTE is:

<details>
  <summary>Click to expand the code block</summary>

```sql
,host_vms as (
    select
        host_dev.device_pk,
        max(vm.last_changed) as max_vm_last_changed,
        json_agg(json_build_object(
            'name', vm.name,
            'ip', vm_ip.ip_address,
            'os', vm.os_name,
            'uuid', lower(vm.uuid),
            'cpu', case when vm.core_per_cpu is not null and vm.total_cpus is not null
                        then concat(vm.core_per_cpu * vm.total_cpus, ' vCPU')
                        else null end,
            'memory', case when vm.ram is not null
                        then concat(
                            case
                                when vm.ram_size_type = 'MB' then vm.ram / 1024
                                when vm.ram_size_type = 'TB' then vm.ram * 1024
                                else vm.ram
                            end, ' GB')
                        else null end
        ) ORDER BY vm.name) as vms_json
    from view_device_v2 host_dev
    inner join view_device_v2 vm
        on vm.virtual_host_device_fk = host_dev.device_pk
        and lower(vm.type) = 'virtual'
        and lower(vm.virtualsubtype) = 'vmware'
        and (vm.details->>'template' is null or (vm.details->>'template')::boolean = false)
    left join network_ip vm_ip on vm_ip.device_fk = vm.device_pk
    where host_dev.virtual_host and lower(host_dev.os_name) like '%esxi%'
    group by host_dev.device_pk
)
```

</details>

In the DOQL v1 task, the CTE uses `view_device_v1`, `vm.cpucore * vm.cpucount`, and `vm.virtual_subtype`, and it does not filter out VM templates:

<details>
  <summary>Click to expand the code block</summary>

```sql
,host_vms as (
    select
        host_dev.device_pk,
        max(vm.last_changed) as max_vm_last_changed,
        json_agg(json_build_object(
            'name', vm.name,
            'ip', vm_ip.ip_address,
            'os', vm.os_name,
            'uuid', lower(vm.uuid),
            'cpu', case when vm.cpucore is not null and vm.cpucount is not null
                        then concat(vm.cpucore * vm.cpucount, ' vCPU')
                        else null end,
            'memory', case when vm.ram is not null
                        then concat(
                            case
                                when vm.ram_size_type = 'MB' then vm.ram / 1024
                                when vm.ram_size_type = 'TB' then vm.ram * 1024
                                else vm.ram
                            end, ' GB')
                        else null end
        ) ORDER BY vm.name) as vms_json
    from view_device_v1 host_dev
    inner join view_device_v1 vm
        on vm.virtual_host_device_fk = host_dev.device_pk
        and lower(vm.type) = 'virtual'
        and lower(vm.virtual_subtype) = 'vmware'
    left join network_ip vm_ip on vm_ip.device_fk = vm.device_pk
    where host_dev.virtual_host and lower(host_dev.os_name) like '%esxi%'
    group by host_dev.device_pk
)
```

</details>

The following column was added to the `SELECT` statement:

```sql
,COALESCE(host_vms.vms_json::text, '[]') as vms_json
```

And the following join was added:

```sql
LEFT JOIN host_vms ON view_device_v2.device_pk = host_vms.device_pk
```

In the DOQL v1 task, the join is:

```sql
LEFT JOIN host_vms ON view_device_v1.device_pk = host_vms.device_pk
```

The following field element was added under the `VMware VCenter Host` header:

### Change Detection Updated

The incremental sync now compares the most recent change to the host or its VMs with the last sync time, and it always includes ESXi hosts.

In the three DOQL v2 tasks, the `doql-suffix` attribute of the `<mapping>` element was changed from:

```sql
where view_device_v2.last_changed>'%s'
```

To the following:

```sql
where (GREATEST(view_device_v2.last_changed, host_vms.max_vm_last_changed)>'%s' or (view_device_v2.virtual_host and lower(view_device_v2.os_name) like '%%esxi%%'))
```

In the DOQL v1 task, the same change was made with `view_device_v1` instead of `view_device_v2`.

### VMware VM UUID Logic Updated

For a VMware VM, `uuid` is now the lowercased BIOS UUID only when that UUID is unique. Otherwise, it is `concat_ws('_', vm_manager_instance_id, vm_manager_ref_id)`.

This change applies to the two newest DOQL v2 tasks:

```xml
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_min_version="19.08.00">
<task enable="true" name="Devices" type="asset" description="Copy Servers from Device42 to Freshservice using DOQL v2" d42_max_version="19.07.99" d42_min_version="19.04.00">
```

A new `bios_shared` CTE was added to the `doql` attribute of the `<resource>` element. It finds BIOS UUIDs that more than one device has:

```sql
bios_shared AS (
    SELECT lower(d.uuid) AS bios FROM view_device_v2 d WHERE NULLIF(d.uuid, '') IS NOT NULL
    GROUP BY lower(d.uuid) HAVING count(*) > 1
),
```

And the following join was added:

```sql
LEFT JOIN bios_shared ON bios_shared.bios = lower(view_device_v2.uuid)
```

In the `uuid` expression, the VMware VM line:

```sql
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware') then lower(view_device_v2.uuid)
```

Was changed to the following:

<details>
  <summary>Click to expand the code block</summary>

```sql
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware' and NULLIF(view_device_v2.uuid, '') IS NOT NULL and bios_shared.bios IS NULL) then lower(view_device_v2.uuid)
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware' and (view_device_v2.details->> 'vm_manager_instance_id' IS NULL OR view_device_v2.details->> 'vm_manager_instance_id' = '' OR view_device_v2.vm_manager_ref_id IS NULL OR view_device_v2.vm_manager_ref_id = '')) then null
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware') then concat_ws('_',view_device_v2.details ->> 'vm_manager_instance_id', view_device_v2.vm_manager_ref_id)
```

</details>

In the `instance_id` expression, the VMware VM value now ends in `vm_manager_ref_id` instead of the UUID. The VMware VM line was changed from:

```sql
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware') then concat_ws('_',view_device_v2.details ->> 'vm_manager_instance_id', lower(view_device_v2.uuid))
```

To the following:

```sql
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware') then concat_ws('_',view_device_v2.details ->> 'vm_manager_instance_id', view_device_v2.vm_manager_ref_id)
```

The `null` check line before it was also changed from:

```sql
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware' and (view_device_v2.details->> 'vm_manager_instance_id' IS NULL OR view_device_v2.details->> 'vm_manager_instance_id' = '' OR view_device_v2.uuid IS NULL OR view_device_v2.uuid = '')) then null
```

To the following:

```sql
when (lower(view_device_v2.type) = 'virtual' AND lower(view_device_v2.virtualsubtype) = 'vmware' and (view_device_v2.details->> 'vm_manager_instance_id' IS NULL OR view_device_v2.details->> 'vm_manager_instance_id' = '' OR view_device_v2.vm_manager_ref_id IS NULL OR view_device_v2.vm_manager_ref_id = '')) then null
```

## Software Tasks

The `Software` task was split into two tasks, one for Device42 19.07.00 and later and one for earlier versions.

The existing task:

```xml
<task enable="true" name="Software" type="software" description="Copy Softwares from Device42 to Freshservice using DOQL">
```

Was replaced with the following tasks:

```xml
<task enable="true" name="Software" type="software" description="Copy Softwares from Device42 to Freshservice using DOQL" d42_min_version="19.07.00">
<task enable="true" name="Software" type="software" description="Copy Softwares from Device42 to Freshservice using DOQL" d42_max_version="19.06.99">
```

### Software Grouping Updated

In both tasks, software with the same name in different letter cases is now grouped as one item. The `last_changed` value now uses the most recent change instead of the oldest.

The `doql` attribute of the `<resource>` element was changed from:

```sql
select * from (select min(software_pk) as d42_pagination_key, trim(name) as name, 'discovered' as software_type, min(view_software_v1.notes) as notes, 'desktop' as application_type, min(last_changed) as last_changed from view_software_v1 where lower(software_type) != 'ignored' group by trim(name)) a
```

To the following in the `d42_max_version="19.06.99"` task:

```sql
select * from (select min(software_pk) as d42_pagination_key, min(trim(name)) as name, 'discovered' as software_type, min(view_software_v1.notes) as notes, 'desktop' as application_type, max(last_changed) as last_changed from view_software_v1 where lower(software_type) != 'ignored' group by lower(trim(name))) a
```

### Application Type Mapping Updated

In the `d42_min_version="19.07.00"` task, the Freshservice application type now comes from the Device42 deployment type, instead of always being `desktop`. The SaaS, mobile, and desktop types map directly, and the server type maps to desktop.

The `doql` attribute of the `<resource>` element is:

```sql
select * from (select min(software_pk) as d42_pagination_key, min(trim(name)) as name, 'discovered' as software_type, min(view_software_v1.notes) as notes, min(case lower(trim(deployment_type)) when 'saas' then 'saas' when 'mobile' then 'mobile' when 'desktop' then 'desktop' when 'server' then 'desktop' end) as application_type, max(last_changed) as last_changed from view_software_v1 where lower(software_type) != 'ignored' group by lower(trim(name))) a
```

In both tasks, `skip-update="true"` was added to the `application_type` field element.

## Delete Asset Relationships Tasks

The `Delete asset relationships from Freshservice that do not exist in Device42` tasks received three changes.

### VMware VM Filter Added

The same `vm_device` filter as in the [Create Relationship Between Host and Virtual Machine task](#create-relationship-between-host-and-virtual-machine-task) was added to all three tasks:

```xml
<task enable="true" type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" d42_min_version="19.08.00">
<task enable="true" type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" d42_min_version="19.05.00" d42_max_version="19.07.99">
<task enable="true" type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" d42_max_version="19.04.99">
```

The `WHERE` clause of the `vm_device` CTE was changed from:

```sql
WHERE  lower(d.type) = 'virtual'
```

To the following:

```sql
WHERE  lower(d.type) = 'virtual' and lower(coalesce(d.virtual_subtype, '')) <> 'vmware'
```

### VMware vCenter Relationships Removed

The VMware vCenter `UNION` branches were removed from these two tasks:

```xml
<task enable="true" type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" d42_min_version="19.08.00">
<task enable="true" type="asset_relationship" description="Delete asset relationships from Freshservice that do not exist in Device42" d42_min_version="19.05.00" d42_max_version="19.07.99">
```

The removed branches used the `rels`, `datacenters`, `datastores`, and `networks` CTEs, and covered these relationship pairs:

- `Contains` and `Contained By`
- `Used By` and `Uses`
- `Provides storage for` and `Stored on`
- `Has Registered` and `Is Registered On`
- `Provides` and `Provided By`
- `Connects` and `Connected By`
- `Defines Resources for` and `Gets Resources from`
- `Has` and `Is Attached To`

### Database Relationships Added

Five `UNION` branches for database relationships were added to the same two tasks. They cover these relationships:

- A database instance is `Hosted On` its device.
- A database instance `Contains` a database or schema.
- A database instance `Contains` a database file.
- A database or schema `Contains` a database file.
- A database instance `Contains` a database instance (`db_instance_container`).

For example, the following branch was added for database instances and their devices:

<details>
  <summary>Click to expand the code block</summary>

```sql
UNION

SELECT
       COALESCE(NULLIF(r_from.resource_name, ''), r_from.identifier) AS dependent_device_name,
       FORMAT('Resource-%s', r_from.resource_pk)   AS dependent_device_device42_id,
       'Hosted On'                                 AS downstream_relationship,
       d.name                                      AS dependency_device_name,
       FORMAT('Device-%s', d.device_pk)            AS dependency_device_device42_id,
       'Hosts'                                     AS upstream_relationship
FROM   view_resource_v2 r_from
JOIN   view_appcomp_resources_v2 ar
ON     ar.resource_fk = r_from.resource_pk
JOIN   view_appcomp_v1 a
ON     a.appcomp_pk = ar.appcomp_fk
JOIN   view_device_v1 d
ON     d.device_pk = a.device_fk
WHERE  lower(r_from.vendor_resource_type) = 'database instance'
```

</details>
